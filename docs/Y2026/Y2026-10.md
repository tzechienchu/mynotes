Circuitron is an agent-driven PCB design prototyper that converts natural language requirements into SKiDL scripts, KiCad schematics, and PCB layout files. It integrates a multi-agent pipeline with advanced reasoning and retrieval-augmented capabilities.

---

💾[SKiDL Skills Plugin for Claude Code](https://github.com/nickkraakman/skidl-skills)

Designing circuit boards is hard, especially for a hobbyist like me with no electrical engineering background.

With the advent of AI, I was hoping these new tools would be able to help me build the PCBs of my dreams, but I was wrong...

LLMs (understandibly) suck at spatial reasoning, but luckily they are great at writing code!

SKiDL allows you to define electronic circuits using Python code, and my Claude Code plugin adds AI agents and skills on top of it to help you code your way to a full-fledged KiCad netlist.

This should get you 80% of the way to having a working PCB in your hands!

What remains is parts placement and routing, which is actively being solved by Seve Ibarluzea as we speak.

📑[How to use SKiDL for PCB Design](https://siliconwit.com/education/pcb-design-kicad/code-based-pcb-design-kicad-scripting/)

### Max96716F and Max96717 SPI Tunnelling Issue.

Search "GMSL2 General Users Guide" 

You will find many information about how to control SPI in this Document.

    I want to use SerDes SPI back channel to access remote SPI Slave Device.
    I write a Deserializer Side MCU to send SPI command.
    And try to loop back from remote side.
    The result is MOSI and MISO is working on remote side. 
    But No SS1 and SCLK on Serializer Side.
    I can get the loop back data on Deserializer Side MCU.

    I though it was the issue on how to set regsiters of Serializer. 
    AI provide a lot of information about how to set registers.
    But not on Deserializer Side's MCU Control Program.

    Intereresting enough is 
    there is no information about "GMSL2 General Users Guide" on the chip data sheet.
    Just link on the chip web page.
